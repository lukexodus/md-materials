## Nelder-Mead Simplex Method

### Overview

The Nelder-Mead method (1965) is one of the most widely used derivative-free optimization algorithms for unconstrained minimization of a scalar function $f: \mathbb{R}^n \to \mathbb{R}$. It maintains a **simplex** — a geometric figure of $n+1$ vertices in $n$-dimensional space — and iteratively transforms this simplex through reflection, expansion, contraction, and shrinkage operations, using only function value comparisons at the vertices. No gradients or Hessians are computed or approximated at any point.

Note: Nelder-Mead should not be confused with the simplex method for linear programming (Dantzig's algorithm) — they are unrelated despite the shared term "simplex," which here refers purely to the geometric figure of $n+1$ points.

### The Simplex Structure

**Key Points**

- A simplex in $n$ dimensions has $n+1$ vertices. In 2D, this is a triangle; in 3D, a tetrahedron; in general $n$-D, a generalized polytope with $n+1$ points.
- At each iteration, the vertices are ranked by function value from best to worst:

$$f(x_1) \le f(x_2) \le \dots \le f(x_{n+1})$$

where $x_1$ is the best vertex and $x_{n+1}$ is the worst.

- The algorithm's core idea is to replace the worst vertex $x_{n+1}$ with a better point, generated by reflecting, expanding, or contracting relative to the **centroid** of the remaining $n$ best vertices:

$$\bar{x} = \frac{1}{n} \sum_{i=1}^{n} x_i$$

(note the centroid excludes $x_{n+1}$, the worst point).

### The Four Core Operations

**Reflection**

The worst point is reflected through the centroid of the remaining points:

$$x_r = \bar{x} + \alpha(\bar{x} - x_{n+1})$$

with reflection coefficient $\alpha > 0$ (standard choice $\alpha = 1$).

- If $f(x_1) \le f(x_r) < f(x_n)$, the reflected point is accepted, replacing $x_{n+1}$.

**Expansion**

If the reflected point is better than the current best ($f(x_r) < f(x_1)$), the algorithm tries extending further in the same direction, since this suggests a productive descent direction:

$$x_e = \bar{x} + \gamma(x_r - \bar{x})$$

with expansion coefficient $\gamma > 1$ (standard choice $\gamma = 2$).

- If $f(x_e) < f(x_r)$, accept $x_e$; otherwise, accept $x_r$ (the reflection is kept as a fallback).

**Contraction**

If the reflected point is worse than the second-worst vertex ($f(x_r) \ge f(x_n)$), the simplex contracts toward the centroid rather than continuing to expand outward. Two variants:

- **Outside contraction** (if $f(x_n) \le f(x_r) < f(x_{n+1})$):

$$x_c = \bar{x} + \beta(x_r - \bar{x})$$

- **Inside contraction** (if $f(x_r) \ge f(x_{n+1})$):

$$x_c = \bar{x} - \beta(\bar{x} - x_{n+1})$$

with contraction coefficient $0 < \beta < 1$ (standard choice $\beta = 0.5$). If the contracted point improves on $x_{n+1}$, it is accepted.

**Shrinkage**

If contraction fails to produce an improvement, the entire simplex is shrunk toward the best point $x_1$:

$$x_i \leftarrow x_1 + \sigma(x_i - x_1), \quad i = 2, \dots, n+1$$

with shrinkage coefficient $0 < \sigma < 1$ (standard choice $\sigma = 0.5$). This is the only operation that modifies *all* vertices except the best one simultaneously, and is typically invoked far less often than reflection.

### Algorithm Flow

```mermaid
flowchart TD
    A[Initialize simplex with n+1 vertices] --> B[Sort vertices by f value: best to worst]
    B --> C[Compute centroid of n best points, excluding worst]
    C --> D[Reflect worst point: compute x_r]
    D --> E{f(x_r) less than f(best)?}
    E -- Yes --> F[Try expansion x_e]
    F --> G{f(x_e) less than f(x_r)?}
    G -- Yes --> H[Accept x_e, replace worst]
    G -- No --> I[Accept x_r, replace worst]
    E -- No --> J{f(x_r) less than f(second worst)?}
    J -- Yes --> I
    J -- No --> K[Try contraction x_c]
    K --> L{Contraction improves worst point?}
    L -- Yes --> M[Accept x_c, replace worst]
    L -- No --> N[Shrink entire simplex toward best point]
    H --> O{Convergence criterion met?}
    I --> O
    M --> O
    N --> O
    O -- No --> B
    O -- Yes --> P[Return best vertex]
```

### Standard Coefficient Values

| Coefficient | Symbol | Standard Value | Role |
|---|---|---|---|
| Reflection | $\alpha$ | 1 | Controls how far the worst point is reflected through the centroid |
| Expansion | $\gamma$ | 2 | Controls how far to extend beyond a successful reflection |
| Contraction | $\beta$ | 0.5 | Controls how far to pull back toward the centroid on failure |
| Shrinkage | $\sigma$ | 0.5 | Controls how tightly the simplex collapses toward the best point |

These are the values originally proposed by Nelder and Mead and remain the most common defaults in implementations (e.g., `scipy.optimize.minimize(method='Nelder-Mead')`), though adaptive variants that scale coefficients with dimension $n$ have also been proposed in later literature.

### Initialization

- The initial simplex requires $n+1$ starting points. A common construction: start from a single point $x_0$ and generate the remaining $n$ vertices by perturbing one coordinate at a time:

$$x_i = x_0 + h \, e_i, \quad i = 1, \dots, n$$

where $e_i$ is the $i$-th standard basis vector and $h$ is a step size (often 5–10% of the initial guess's magnitude, or a fixed absolute value when $x_0$ is near zero).

- **Key Points**: The size and shape of the initial simplex materially affects performance — too small risks premature convergence to a local region without adequate exploration; too large may waste evaluations before the simplex adapts to local scale. [Inference] this sensitivity to initial simplex geometry is a widely noted practical concern, though the precise degree of impact is problem-dependent.

### Convergence Criteria

Common stopping rules (used individually or combined):

- **Domain convergence**: the simplex vertices become close together, e.g., $\max_i \|x_i - x_1\| < \epsilon_x$.
- **Function value convergence**: the spread of function values across vertices becomes small, e.g., $|f(x_{n+1}) - f(x_1)| < \epsilon_f$.
- **Maximum iterations or function evaluations reached** (a practical safeguard against non-termination).

### Convergence Theory and Limitations

**Key Points**

- Nelder-Mead has **no general convergence guarantee** to a stationary point, even for smooth convex functions, in dimensions $n \ge 2$. This is a well-documented theoretical result, not merely a practical concern.
- McKinnon (1998) constructed explicit smooth, strictly convex two-dimensional counterexamples where the Nelder-Mead simplex provably converges to a non-stationary point — the simplex can degenerate (collapse to a lower-dimensional subspace) before reaching the minimizer.
- Despite this, Nelder-Mead performs well empirically on many low-dimensional, moderately well-behaved problems, which explains its continued popularity relative to its weak theoretical guarantees. [Inference] the gap between weak theoretical guarantees and generally reasonable empirical performance on small problems is widely discussed in the DFO literature, though "well" is necessarily an informal, problem-dependent characterization.
- Convergence reliability degrades further as dimension increases; Nelder-Mead is generally not recommended beyond roughly 10–20 variables. [Unverified] — exact practical dimension limits vary by implementation and problem, and different sources cite different rough thresholds.

### Practical Considerations

- **Restart strategies**: Because of the degeneracy risk, practical implementations often restart the algorithm with a fresh simplex centered at the current best point once stagnation is detected, which helps recover from simplex degeneracy.
- **Sensitivity to scaling**: Since Nelder-Mead relies on geometric relationships between vertices, poorly scaled variables (e.g., one variable ranging over $10^{-3}$ and another over $10^{3}$) can distort the simplex's effectiveness; rescaling variables to comparable magnitudes is a common preprocessing step.
- **No use of past evaluation history beyond the current simplex**: unlike model-based DFO methods (e.g., BOBYQA), Nelder-Mead discards information from replaced vertices, which is part of why model-based methods can be more sample-efficient in practice, particularly for expensive-to-evaluate functions. [Inference] the relative sample-efficiency gap depends on the specific problem and implementation being compared.

### Example (Conceptual Walkthrough)

**Example**

Minimizing $f(x, y) = (x-3)^2 + (y-2)^2$ (a simple convex bowl, for illustration only):

1. Initialize a triangle with vertices $x_1 = (0,0)$, $x_2 = (1,0)$, $x_3 = (0,1)$.
2. Evaluate $f$ at each: $f(x_1) = 13$, $f(x_2) = 8$, $f(x_3) = 10$.
3. Rank: best $= x_2$ (8), worst $= x_1$ (13). Centroid of remaining two: $\bar{x} = (0.5, 0.5)$.
4. Reflect: $x_r = \bar{x} + (\bar{x} - x_1) = (1, 1)$, giving $f(x_r) = 5$ — better than the current best, so try expansion.
5. Expand: $x_e = \bar{x} + 2(x_r - \bar{x}) = (1.5, 1.5)$, giving $f(x_e) = 2.5$ — improves further, so accept $x_e$, replacing $x_1$.
6. Repeat with the new simplex $\{x_2, x_3, x_e\}$, re-ranking and continuing until convergence criteria are met.

This toy example converges quickly because the function is smooth and convex with a simple geometry; performance on non-convex, noisy, or ill-scaled functions can differ substantially in practice.

### Common Pitfalls

- Using Nelder-Mead on high-dimensional problems where it is known to degrade significantly in reliability and efficiency.
- Assuming convergence to a local minimum has occurred simply because the algorithm terminated — termination only indicates the stopping criterion was satisfied, not necessarily proximity to a true stationary point, given the lack of general convergence guarantees.
- Neglecting to rescale badly conditioned variables before optimization, leading to a distorted, inefficient simplex geometry.
- Relying on a single run without restarts for problems where simplex degeneracy is a known risk.
